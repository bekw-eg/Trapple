# Trapple — разбиение трёх экранов на UI-элементы

Разделены три исходных растровых макета: **Карта миров**, **Мастерская**, **Гардероб**.

## Внутри набора

- `full_screens/` — 3 изображения целиком; у «Карты миров» удалён связанный чёрный фон вокруг интерфейса.
- `common/` — общая вывеска, вкладки (активные/неактивные), закрытие, меню, декоративные фрагменты и приблизительно изолированный пиксельный персонаж.
- `worlds/` — 4 полные карточки, 4 превью, 4 кнопки «Выбрать», 4 номера мира, звезда, замок, индикаторы и баннер секретных миров.
- `workshop/` — 3 полные карточки прокачки, 3 иконки, 3 кнопки, 3 индикатора уровня, валюта, заголовок и подсказка.
- `wardrobe/` — большая карточка персонажа, 4 строки скинов, 4 миниатюры, 4 бейджа статуса, заголовок и подсказка.
- `guides/` — 3 изображения с подписанными прямоугольниками крупных компонентов.
- `asset_manifest.json/.csv` — точные исходные координаты обрезки и типы элементов.
- `unity_hotspots.json` — примерные зоны нажатий на кнопки, с координатами от верхнего левого угла и нормированными координатами.

## Важное ограничение исходников

Это **плоские изображения, а не PSD/Figma со слоями**. Полностью и без артефактов отделить каждую деревянную рамку, текст, яблоки и тени от соседних пикселей невозможно. Картинки типа `composite` содержат фрагменты окружающего оформления. Картинки типа `approx_masked` имеют приближённую прозрачную маску, которую желательно доработать вручную. **Не считать все PNG чистыми production-ready прозрачными спрайтами.** В кнопках уже есть русский текст, в карточках уже нарисованы уровни и значения.

## Рекомендуемая Unity UI-иерархия

```
Canvas (CanvasScaler, Scale With Screen Size)
├── CommonFrame / Background (Image)
├── Branding (Logo)
├── Header
│   ├── WorkshopTab (Button + Image)
│   ├── WorldMapTab (Button + Image)
│   ├── WardrobeTab (Button + Image)
│   └── CloseButton (Button + Image)
├── WorldMapPanel
│   ├── Title (TextMeshProUGUI)
│   ├── WorldCards (HorizontalLayoutGroup)
│   │   └── WorldCard x4 (preview, title, star count, progress, lock overlay, button)
│   └── SecretWorldsBanner
├── WorkshopPanel
│   ├── CurrencyCounter
│   ├── UpgradeCards (HorizontalLayoutGroup)
│   │   └── UpgradeCard x3 (icon, title, description, level x3, delta, button)
│   └── Hint
└── WardrobePanel
    ├── CharacterPreview (Image + TextMeshPro)
    ├── SkinList (VerticalLayoutGroup)
    │   └── SkinRow x4 (icon, name, description, status badge)
    └── Hint
```

**Каждая из трёх панелей — отдельный объект**, активна только одна. `WorldCard`, `UpgradeCard`, `SkinRow` должны быть шаблонами-представлениями, которым код подставляет данные. Не создавать по четыре отдельных типа скриптов.

### Быстрый прототип (без полной перевёрстки)

1. Импортировать `full_screens/*.png` в Unity с `Texture Type: Sprite (2D and UI)`.
2. Создать `Canvas` и по одному `Image` на каждый экран; включать один Image в зависимости от активной вкладки.
3. Наложить поверх них прозрачные `Button` с координатами из `unity_hotspots.json`.
4. С помощью OnClick переключать экраны, выбирать мир, открывать улучшение или менять скин.
5. Для прототипа не использовать одновременно вырезанные карточки и полный экран — будет дубль изображения.

### Для финального интерфейса

- Рамки и фоны перерисовать/экспортировать как самостоятельные спрайты, желательно 9-slice, без текста.
- Заголовки, описания, стоимость улучшения и прогресс вынести в `TextMeshProUGUI`.
- Состояния: `Selected`, `Available`, `Locked`, `Upgradable`, `InsufficientFunds` реализовать данными и цветами/иконками, а не отдельными полноэкранными скриншотами.
- Для пиксельного героя поставить `Filter Mode: Point (no filter)`; для иллюстрированных рамок допустим `Bilinear`.
- Экранные изображения имеют **разные исходные размеры и пропорции**. Не подставлять их в Canvas как одинаковую геометрию без выравнивания/сохранения пропорций.
- По дизайну фигурирует валюта «семечки» с символом яблока; продумать единое название и пиктограмму. На снимках мира прогресс 0/30, у мастерской 0/3, в гардеробе 4/12 — это демонстрационные данные, не достоверные значения игрового сохранения.

## Примечания по контенту

Текущие макеты показывают улучшения скорости, ловкости и прыжка. Для игрового баланса надо отдельно проверить, не делают ли постоянные улучшения ловушки проходимыми слишком легко. Также на макете «Яблочная поляна» — полноценная карточка мира, хотя в структуре уровней этот мир ранее обсуждался как обучение. Это вопрос игрового дизайна, не ошибка обрезки.
