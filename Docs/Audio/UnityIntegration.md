# План интеграции в Unity

**Статус: предложение, не реализованный MusicManager.**
Аудио ещё не получено; существующие C#-скрипты и сериализованные игровые
объекты не менялись. Интеграцию музыкальных событий нужно согласовать с
разработчиком GameManager, UI и боссов через отдельный PR.

## Результат анализа проекта

База этого PR: origin/main, commit 0ec7fe6, Unity 6000.6.0f1.
Также прочитана исходная рабочая ветка feature/expand-levels на 7b73f7b;
её незамерженный контент в этот PR не включён.

На main в EditorBuildSettings зарегистрированы MainMenu, Hub, Tutorial,
BossTest и TrappleUI. Сцены Factory и LavaFortress отсутствуют.
DeceptiveForest_Level02 присутствует в изученной feature/expand-levels,
но отсутствует на выбранной main; назначать её музыку после интеграции сцены.

В Assets нет WAV/OGG/MP3 и в runtime-скриптах не найдены AudioSource, AudioClip
или MusicManager. HubAmbience управляет визуальными движениями, а не звуком.
GameManager уже создаёт постоянный singleton и устанавливает AudioListener.volume.
GameInterface и HubUIController регулируют общую громкость.
У WorkshopTransitionController есть State (Outside/Entering/Inside/Exiting),
но нет события смены состояния; мастерская — часть Hub, не отдельная сцена.
BossHealth предоставляет HealthChanged и Died; BossController — FightFinished.
BossPhaseController предоставляет CurrentPhase, но не PhaseChanged.

## Предлагаемый MusicManager

Один prefab MusicSystems с MusicManager в отдельном namespace Trapple.Audio,
каталогом ScriptableObject и двумя заранее созданными AudioSource A/B для фона,
плюс одним AudioSource для джинглов. Это ограниченный пул из трёх источников,
а не новый источник при каждом входе в сцену. Поля каталога, mixer group,
громкости и времена переходов — через [SerializeField].

Один экземпляр сохраняется через DontDestroyOnLoad, лишний уничтожается
до подписки на события и запуска аудио. Статическую ссылку сбрасывать при
SubsystemRegistration, подписки снимать при уничтожении. При отключённом
domain reload и прямом открытии gameplay-сцены поведение также проверить.

Предлагаемые операции (это контракт, не существующий API):

- PlaySceneMusic(scenePath): определить клип после загрузки сцены; повтор того
  же ID не перезапускает проигрывание.
- SetContext(Workshop/Lobby): переключить музыку внутри той же сцены.
- BeginBoss(trackId): сохранить фоновый контекст и включить босса.
- SetBossPhase(1/2): запросить переход по музыкальной сетке.
- EndBoss(): отменить ожидающую фазу, приглушить бой, сыграть Boss Defeated
  один раз, затем вернуть актуальный фон.
- PlayJingle(id): отдельный короткий сигнал; повторные callbacks одного события
  не дублируют джингл.
- SetMusicVolume(value): сохранить Trapple.MusicVolume и регулировать music bus.

Не использовать AudioListener.volume для отдельного music slider: существующий
master-volume должен продолжать воздействовать на всю игру. Новый music bus
настроить внутри AudioMixer, SFX оставить независимыми. Источники 2D,
playOnAwake=false, background loop=true, jingle loop=false, pitch=1.
Это соответствует описанию свойств [AudioSource в Unity 6](https://docs.unity.com/en-us/engine/6000.0/script-reference/unityengine/audiosource).

Обычная смена сцен: fade 0.5–1.0 s; для несвязанных тональностей можно сначала
приглушить исходный трек и затем поднять новый. Для коррелирующих фаз использовать
линейный crossfade, чтобы одинаковые слои не прибавляли лишний уровень.
Громкость вычислять от пользовательского уровня и огибающей перехода,
а не записывать пользовательскую настройку в каждом кадре fade.

Держать только один актуальный запрос перехода. При новом запросе отменять
ожидающий старт старого клипа; никогда не менять уже играющий клип без fade.
При A→B→C за короткое время завершить/прервать предыдущий переход от текущих
уровней. Проверить также null-клип: сохранить доступный фон или перейти в
управляемую тишину, не выбрасывать исключение.

## Синхронизация фаз Magma

Обе версии: 160 BPM, 128 тактов, 4/4, 192 s, 9 216 000 кадров при 48 kHz.
Восемь аккордов Dm | Dm | Bb | Bb | Gm | Gm | A7 | A7 повторяются
в одинаковых местах. Вторая фаза быстрее по рисунку, но BPM не меняется.

Сохранить DSP-время первого запуска. За 0.2 s или больше до границы, с учётом
времени загрузки, выбрать следующую доступную тактовую границу:
barDuration = 4 × 60 / 160 = 1.5 s. Рассчитать её номер от начала общего
транспорта, затем modulo 128 — позицию назначения. На свободном источнике
выставить соответствующий timeSamples и запланировать запуск в это DSP-время.
Не начинать Phase 2 с начала файла при произвольной гармонической позиции.

Unity рекомендует [PlayScheduled](https://docs.unity.cn/6000.6/Documentation/ScriptReference/AudioSource.PlayScheduled.html)
для стыковки клипов по DSP-времени независимо от частоты кадров.
Для импортированного sample rate пересчитать позицию; PCM timeSamples
нельзя копировать между клипами с разной частотой. После старта выполнить
короткий линейный crossfade около одной доли (0.375 s), проверить итоговый уровень.
Если клип не готов к дедлайну — выбрать следующую границу, сохраняя Phase 1.

Смерть босса, смена сцены и перезапуск боя отменяют pending phase. При новом
бое сбросить транспорт и фазу. Не повышать AudioSource.pitch для «ускорения»:
это изменит высоту и разрушит совместимость аранжировок.

## События существующих систем

Для текущего BossTest момент начала можно задать отдельным адаптером на арене.
FightFinished использовать как единственный источник Boss Defeated; не подписывать
тот же джингл одновременно на Died и FightFinished.
За CurrentPhase наблюдать в одном адаптере с запоминанием предыдущего значения,
либо добавить явное PhaseChanged отдельным согласованным изменением.
Не дублировать условие порога здоровья: текущая фаза 2 начинается строго ниже
настроенного порога, а не ровно на нём.

Для мастерской адаптер отслеживает Entering/Inside и Exiting/Outside либо
получает новые согласованные события. Начинать мягкий переход при входе,
возвращать Lobby при выходе или Cancel. Отдельный вход Workshop в TrappleUI
также должен задавать контекст — sceneLoaded здесь не сработает.

Level Complete запускать после подтверждённого достижения цели один раз;
Victory оставить для завершения игры, Game Over — для экрана поражения.
Не играть Game Over автоматически на каждую быструю смерть с respawn.
Upgrade Purchased запускать только после успешной покупки, не по нажатию
кнопки или отказу из-за недостатка валюты. Во время сигнала приглушать фон.

При паузе предлагается продолжать музыку тише; fades используют unscaled time.
Если будет введена AudioListener.pause, отдельно определить её влияние на
транспорт: DSP-время при остановке аудиосистемы нельзя смешивать с игровым timer.

## Импорт и проверка

Начать с PCM и сохранённой частоты: Force To Mono=false, Normalize не применять.
Короткие джинглы — Decompress On Load. Для длинного обычного фона рассмотреть
Streaming после проверки на целевой платформе. Для точного фазового seek
Magma сначала использовать загруженный PCM; оценить память и затем отдельно
проверить потоковый вариант, если он нужен. Два декодированных stereo-клипа
192 s × 48 kHz × 2 канала × 4 байта float требуют примерно 141 MiB вместе,
без учёта дополнительных накладных расходов.

Параметры загрузки и компрессии описаны в
[Audio Clip Import Settings](https://docs.unity3d.com/6000.0/Documentation/Manual/class-AudioClip.html).
Настройки платформы проверять отдельно: исходный WAV сам по себе не означает,
что собранная игра использует PCM.

После реализации проверить: прямой запуск каждой сцены; Menu→Hub→Workshop→Hub;
быстрые повторные переходы; pause/resume при fade; volume=0; respawn без
навязчивого рестарта темы; две фазы на разных тактах и рядом со швом; смерть
босса во время pending phase; отсутствие новых AudioSource после десяти
переходов; несколько полных циклов в Editor и Windows build. Сейчас эти
проверки не выполнены — ни клипов, ни нового runtime-кода ещё нет.
