# Death Screen

## Поведение

`PlayerDeath.Die()` по-прежнему блокирует управление и физику Аппи. После
существующей задержки `restartDelay` (0,65 с) вместо автоматического рестарта
открывается экран смерти. Отдельной анимации смерти в текущем обработчике нет;
внешний вид и анимации Аппи не изменены.

`GameManager` управляет состояниями `Dying` и `Dead`. В первом сохраняется время
для существующего завершения смерти, во втором `Time.timeScale = 0`. Пауза,
настройки, HUD и завершение уровня не перекрывают Death Screen. В хабе также
закрывается открытое окно и блокируется ввод взаимодействий до смены сцены.

Экран добавлен в существующий `Resources/Storybook/GameInterface.prefab` и
использует его Canvas Scaler. Полупрозрачный Image перекрывает клики по фону.
Заголовок и счёт используют существующий `Thaleah SDF`, две кнопки — вложенные
экземпляры существующего `PrimaryButton.prefab` с прежним `UIButtonAnimator`.
Отдельный Canvas с порядком 300 обеспечивает показ поверх окон хаба.

- **Respawn:** однократно загружает сцену погибшего персонажа через
  `GameManager.LoadScene`. Это прежний полный рестарт сцены: начальная точка,
  исходное состояние ловушек и предметов. Системы чекпоинтов сейчас нет.
- **Go to the hub:** использует `HubSceneFlowController.ReturnToHub`. При прямом
  запуске уровня без этого сервиса загружает его же `HubScenePath` через
  `GameManager.LoadScene`. Время и управление восстанавливаются.
- **Score:** пока `Score: 0`. Для будущего источника предусмотрен параметр
  `DeathScreenUI.Show(scenePath, currentScore)`. Валюта и таймер не выдаются за очки.
- Любая обычная загрузка сцены скрывает экран. Повторная смерть или повторный
  клик не создают дополнительный UI и не запускают второй переход.

Сохранения, уровни, ловушки, порталы, карта и мастерская не менялись.

## Файлы задачи

В `Assets/_Trapple/`:

- `Scripts/UI/DeathScreenUI.cs` и `.meta` — представление и кнопки.
- `Scripts/Player/PlayerDeath.cs` — подключение после существующей задержки.
- `Scripts/Core/GameManager.cs` — состояния смерти и запоминание сцены игрока.
- `Scripts/UI/GameInterface.cs` — жизненный цикл экрана и исключение конфликтов UI.
- `Resources/Storybook/GameInterface.prefab` — готовый экран с назначенными ссылками.
- `Editor/DeathScreenUIBuilder.cs` и `.meta` — сборка только этого экрана через API Unity.
- `Editor/StorybookUIBuilder.cs` — сохранение экрана при пересборке общего интерфейса.
- `Tests/PlayMode/DeathScreenTests.cs` и `.meta` — функциональная и визуальная проверка.
- `Tests/PlayMode/TutorialTests.cs`, `DeceptiveForestTests.cs`,
  `BossSystemsTests.cs`, `ExpandedLevelTests.cs` — обновлённые проверки рестарта
  по кнопке вместо авторестарта.

Также добавлен этот отчёт `Docs/DeathScreen.md`. Сцены и исходные UI-ассеты не
редактировались. Предыдущие локальные изменения `DeceptiveForest_Level02.unity`
оставлены в рабочей копии и исключены из коммита.

## Воспроизведение проверок

Unity **6000.6.0f1**. Префаб сериализован Unity, YAML вручную не генерировался.
Повторная установка: **Tools → Trapple → Install death screen**. Команда не
открывает, не сохраняет и не меняет игровые сцены.

Результат проверки 28 октября 2026:

- **62/62 PlayMode** — DeathScreenTests, TutorialTests, DeceptiveForestTests,
  BossSystemsTests, ExpandedLevelTests и StorybookUITests; без двух длительных
  тестов полного прохождения и без отдельного визуального теста.
- **1/1 визуальный тест** — все шесть разрешений; полученные кадры просмотрены.
- Компиляция скриптов и установка префаба через Unity завершились успешно.
- `git diff --check` — ошибок нет.

Функциональные тесты: PlayMode, `Trapple.Tests.DeathScreenTests` (визуальный тест
без отдельного флага намеренно пропускается). Проверяются задержка смерти,
заморозка симуляции, конфликты меню, три последовательные смерти, защита от
повторных кликов, EventSystem, raycast/PointerClick, сохранение валюты, улучшений
и миров, обычный спавн хаба, прямой запуск уровня и аддитивная интеграция сцен.

Визуальная проверка: запустить Editor с `-runTests -testPlatform PlayMode
-testFilter Trapple.Tests.DeathScreenTests.CaptureAndCheckResponsiveLayout
-capture-death-screen -force-d3d11`, без `-batchmode` и `-nographics`.
Кадры сохраняются в `Logs/DeathScreenCaptures/`. Автоматически проверяются
центрирование, границы экрана и отсутствие переполнения TMP на 1366×768,
1920×1080, 1024×768, 2560×1080, 720×1280 и 3840×2160.

Проверки выполняются в отдельной копии проекта. Для леса используется
закоммиченная версия сцены; локальные изменения открытого проекта в эту копию
не включены. В проверочной копии также используется отдельное имя продукта для
изоляции PlayerPrefs. Standalone-сборка и полное ручное прохождение не выполнялись.
