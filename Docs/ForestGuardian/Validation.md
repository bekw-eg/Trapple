# Проверка интеграции боссов

Проверка выполнена в установленной Unity **6000.6.0f1** в отдельном рабочем дереве `feature/forest-guardian-progression`. Исходные незакоммиченные Hub/Forest сцены в прежней папке проекта не изменялись.

## Результаты

| Проверка | Результат |
|---|---|
| Компиляция и интеграция через `ForestGuardianBuilder.Build` | Успех; обе игровые сцены, тестовая сцена и префабы сохранены Unity |
| EditMode, окончательный полный прогон | **30/30 passed** |
| PlayMode, уникальные сценарии по последнему результату каждого теста | **135 passed, 0 failed, 2 skipped** |
| Окончательный прогон боя и отрисовки после пересборки префабов | **19/19 passed** |
| Окончательный прогон первого босса, включая сохранение победы | **4/4 passed** |
| Windows x64 Development, все 6 включённых игровых сцен | **Build Finished, Result: Success**, exit 0 |
| `git diff --check` | Успех |

Сводка каждого теста и исходных прогонов: [TestResults.json](TestResults.json).

Число 135 — совокупность уникальных успешных сценариев, а не заявление об одном последнем полном прогоне. Первоначальный полный PlayMode запуск дал 124 passed / 8 failed / 3 skipped. После исправлений соответствующие наборы повторно дали 43 passed / 0 failed / 1 skipped; окончательные 19 проверок боя и 4 проверки первого босса также прошли. Две дополнительные физические проверки появились после первоначального прогона. Уже прошедшие длинные маршруты после этих локальных исправлений повторно не запускались.

Исправлены выявленные условия:

- Старые тесты ждали отсутствия progression-сервиса при прямом входе, трёх лесных уровней и закрытого леса. Теперь они проверяют реальную конфигурацию, новое условие первого босса и доступный контент, не подменяя настройки игры.
- Обратный бросок проверяется из физически доступной точки внутри арены, а не за краем допустимого положения игрока возле стены.
- Интервал тройной волны листьев сокращён до 0,4 секунды; реальное движение и прыжок Appi проходят эту атаку.
- Canvas карты и гардероба вписывается по обеим осям: реальный raycast по кнопке Close проходит и в тестовом окне 640×480.
- Иллюстрированное яблоко проверяется по дочернему artwork; исходный технический SpriteRenderer уже скрывался существующим оформлением уровня.

## Что проверено в Play Mode

- Оба полных маршрута пройдены скриптовым вводом через реальные Physics2D и PlayerController до вступлений боссов: лес — 211 команд, Meadow — 226 команд. Старые ловушки и взаимодействия сохранены.
- Вход на арену, однократное вступление, пропуск, блокировка/возврат управления, пауза, отсутствие расхода времени во вступлении.
- Автоподбор, предел вместимости, запрет повторной выдачи, нулевой запас, cooldown, приоритет старой палки головоломки.
- Полёт реальных Rigidbody2D палок вправо и влево до тела босса, однократный урон и прохождение через дочерние опасные эффекты без ложного урона боссу.
- Три разных предупреждённых атаки, реальная смерть от листа и возможность избежать корня, удара веткой и потока листьев обычным движением/прыжком.
- Две развязки боя, запрет повторной победы и повторного включения завершённого босса.
- Смерть, прежний экран смерти, Retry, восстановление HP/таймера/запаса, отсутствие повторной выдачи предметов чекпоинта.
- Запись завершения обоих миров, восстановление сохранения новым экземпляром progression-сервиса, открытие Factory как записи без выдумывания сцены.
- Прежние boss-, player-, sprint-, hub-, map-, workshop- и UI-сценарии из общего набора.

Тест границы таймера ускоряет окончание счётчика; это проверка условий перехода, а не заявление о ручном 60-секундном прохождении человеком.

Отрисовка боя использует отдельную `ForestGuardianTest` с теми же префабами. Её путь отсутствует в production-конфигурации миров, поэтому победа в визуальном тесте не записывает пользователю пройденный мир.

Не запускались два отдельных opt-in сценария: `DeathScreenTests.CaptureAndCheckResponsiveLayout` и `ExpandedLevelVisualTests.CaptureSectionScenery`. Проверки логики экрана смерти и полных маршрутов выполнены; новые снимки всего старого интерфейса и каждой секции не создавались.

## Сборка и воспроизведение

Windows-сборка: `Builds/Hub/Trapple.exe` (в Git не включается). Команда сборки: `Trapple.Editor.HubBuilder.BuildWindows`.

Для повторения из командной строки Unity: `-batchmode -projectPath <project> -runTests -testPlatform EditMode` либо `PlayMode`, с `-testResults <xml>` и `-logFile <log>`. Для снимков добавить `-testFilter Trapple.Tests.ForestGuardianVisualTests -capture-guardian`, включить графику. Исходные локальные XML/логи лежат в игнорируемой папке `Logs`.

## Оставшиеся ручные проверки

Нужен проход новым игроком для оценки понятности предупреждений, ощущения броска, сложности 60 секунд выживания и управления физической клавиатурой. Автотесты используют production-физику со скриптовым вводом и не заменяют такую оценку. Отдельный ручной запуск экспортированного EXE не выполнялся.

Чекпоинт сохраняется только в текущем сеансе; долгосрочно записывается завершение мира. Для будущего маршрута с пересечениями/полностью наложенными путями понадобятся последовательные route gates. Factory и Lava остаются запланированными мирами без новых сцен.
